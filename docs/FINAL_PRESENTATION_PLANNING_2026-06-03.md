# FoodLink 최종 발표 기획 정리

> 목적: 다음 주 프로젝트 최종 발표에서 사용할 기획 내용을 간결하게 정리한다.
> 기준: 2026년 5월 개발/검증 기록, 제품 문서, git log

---

## 1. 서비스 한 줄 소개

**FoodLink는 버리기 아까운 미사용 여분 식재료를 가까운 공유 냉장고에 맡기고, 근처 사용자가 오늘 바로 가져갈 수 있게 연결하는 로컬 식재료 나눔 앱이다.**

---

## 2. 기획 목적

FoodLink는 사용자가 유통기한이 가까워진 여분 식재료를 발견했을 때, 버리기 전에 쉽게 처리할 수 있는 선택지를 제공한다.

핵심 목적은 세 가지다.

- **공급자**: 남은 식재료를 직접 연락이나 약속 없이 처리
- **수요자**: 근처에서 오늘 바로 쓸 수 있는 식재료 발견
- **공유 냉장고**: 비대면 전달과 보관을 위한 로컬 거점 제공

---

## 3. 해결하려는 문제

### 문제 상황

대학가 1인 가구는 장을 조금 많이 봤거나 일정이 바뀌었을 때, 아직 먹을 수 있지만 곧 버리게 될 식재료를 자주 발견한다.

하지만 식재료 몇 개를 나누기 위해 글을 쓰고, 사람과 연락하고, 시간을 맞추는 과정은 너무 번거롭다.

### 핵심 문제 문장

> 멀쩡하지만 곧 버리게 될 미사용 여분 식재료가 생겼을 때, 사람과 직접 연락하거나 약속을 잡는 과정이 식재료 가치보다 더 귀찮다.

### 기존 대안의 한계

| 기존 대안 | 한계 |
| --- | --- |
| 그냥 버리기 | 가장 빠르지만 아깝고 찝찝함 |
| 냉장고에 더 넣어두기 | 결국 잊히거나 상할 가능성 |
| 친구에게 연락 | 상대에게 부담이 되고 시간 조율 필요 |
| 당근/에브리타임/단톡방 | 글쓰기, 댓글, 약속, 대면 전달이 번거로움 |

---

## 4. 문제 해결 방향

FoodLink는 초과 구매를 예방하는 앱이 아니라, **이미 생긴 여분 식재료를 버리기 전 처리하는 앱**으로 시작한다.

해결 흐름은 다음과 같다.

```text
식재료 발견
  -> 사진 촬영
  -> AI 분석 결과 확인
  -> 공유 냉장고 선택
  -> QR 보관 인증
  -> 근처 사용자 발견/알림
  -> 나눔 신청
  -> QR 수령 인증
  -> 수령 경험 평가/신고
  -> 공급자 신뢰 뱃지 반영
```

FoodLink가 줄이는 마찰:

- 글쓰기 부담
- 직접 연락 부담
- 시간 약속 부담
- 모르는 사람과의 대면 부담
- "누가 가져갈지 모름"에 대한 불확실성
- "정말 좋은 나눔을 받을 수 있는가"에 대한 신뢰 불확실성

## 5. 예상 사용자

### 1차 검증 시장

**대학가 1인 가구**

이 타겟은 최종 시장을 제한하기 위한 것이 아니라, 가장 빨리 검증 가능한 첫 시장이다.

선정 이유:

- 소량 식재료가 자주 남음
- 원룸/기숙사 등 밀집 생활권
- 식비 절약 니즈 존재
- 공유 냉장고가 생활 동선 안에 있으면 이동 마찰이 낮음

### 공급자 페르소나

| 항목 | 내용 |
| --- | --- |
| 이름 | 최재원 |
| 나이 | 24세 |
| 거주 | 전남대 근처 원룸 |
| 상황 | 혼자 살며 장을 가끔 크게 봄 |
| 문제 순간 | 재료를 너무 많이 사서 유통기한이 임박한 식재료를 발견한 순간 |
| 니즈 | 직접 연락 없이 가까운 곳에 맡기고 처리 완료감을 얻고 싶음 |

### 수요자 페르소나

| 항목 | 내용 |
| --- | --- |
| 대상 | 대학가 근처 학생 또는 자취생 |
| 상황 | 오늘 저녁이나 간식에 쓸 재료가 필요함 |
| 니즈 | 식비를 아끼고 싶고, 근처에서 바로 가져갈 수 있는 재료를 찾고 싶음 |
| 회피 | 모르는 사람과 직접 거래하거나 오래 기다리고 싶지 않음 |

## 6. As-Is / To-Be

### 공급자

| 구분 | 내용 |
| --- | --- |
| As-Is | 유통기한이 가까워진 식재료를 발견해도 나눔 과정이 귀찮아 냉장고에 방치하거나 버림 |
| To-Be | 사진을 찍고 가까운 공유 냉장고에 QR로 보관한 뒤 식재료 처리 완료 |

### 수요자

| 구분 | 내용 |
| --- | --- |
| As-Is | 오늘 쓸 재료가 필요해도 직접 거래는 부담스럽고, 무료/저렴한 재료를 찾기 어려움 |
| To-Be | 홈/지도에서 근처 공유 냉장고의 나눔 식재료를 확인하고 신청 후 수령 |

## 7. 핵심 서비스 정책

### 거리 정책

| 정책 | 기준 |
| --- | --- |
| 공급자 보관 냉장고 | 도보 약 5분, 최대 500m 권장 |
| 수요자 푸시 알림 | 냉장고 기준 500m 이내 |
| 홈/지도 탐색 | 사용자 위치 기준 2km 이내 |
| 수령 제한 시간 | 신청 후 30분 |

### 관심 식재료 알림

수요자는 기본적으로 앱을 열어 근처 나눔 식재료를 확인한다. 알림은 앱 사용을 대체하는 것이 아니라, 관심 식재료를 놓치지 않게 하는 보조 장치다.

알림 기준:

- 거리 조건과 관심 품목 조건을 모두 만족할 때 발송
- 하루 최대 2-3회
- 같은 냉장고/같은 품목 중복 알림 제한
- 오전/오후/저녁 식사 전 시간대에 묶음 알림 발송

예시:

```text
저녁에 쓸 관심 재료가 근처에 있어요.
전남대 공유냉장고 · 양파, 바나나 · 도보 4분
```

## 11. 주요 기술적 이슈와 해결

### 1. AI 메타데이터 저장 불일치

문제:

- 등록 직전 AI 결과는 보였지만, 등록 후 홈/상세/지도에서 식재료명이 fallback으로 표시됨

해결:

- 백엔드 `imageToken` sidecar AI 메타데이터 저장/복원 방식으로 수정
- 프론트는 `imageToken`, `fridgeId`, `expirationDate` 중심으로 등록 payload 정리
- VM/API 및 Android 실기기에서 재검증

### 2. AI false-positive와 모델 한계

문제:

- 현재 AI가 비식재료, 스크린샷, 저품질, 다중 객체를 안정적으로 판별하지 못함

해결:

- `Fresh/Mid/Stale` 중심으로 MVP 범위 제한
- confidence 0.9 미만은 등록 차단이 아니라 `확인 필요`로 표시
- 발표에서는 AI를 "식품 안전 보장"이 아니라 "사진 기준 참고 신호"로 설명

### 3. FCM 수신과 알림 라우팅

문제:

- Firebase 설정 부재 시 앱 시작 크래시 가능성
- foreground/background/terminated 상태별 알림 라우팅 검증 필요

해결:

- Firebase Messaging fallback guard 추가
- 실기기 + emulator 2계정으로 FCM 수신, 알림함 기록, 상세 화면 라우팅 검증

### 4. QR lifecycle 시간대 처리

문제:

- timezone 없는 `requestExpiresAt`을 잘못 해석해 신청 직후 만료처럼 보임

해결:

- 서버 lifecycle 시각 UTC 파싱 보강
- 상세, 홈, 받은 나눔 화면에서 30분 수령 제한 시간 정상 표시 확인

### 5. Android 하단 safe-area

문제:

- QR 화면 action grid와 하단 탭이 Android system navigation bar와 겹침

해결:

- `DSScreenFooter` 및 Android navigation fallback inset 적용
- 실기기 QA로 하단 CTA 위치 재검증

### 6. 운영자 콘솔 권한 제어

문제:

- 운영자 콘솔이 일반 사용자에게 노출되면 MVP 범위가 흐려짐

해결:

- `/auth/me`의 `isOperator`, `operatorRole`, `operatorFridgeIds` 기준으로 진입점 제어
- 모바일 앱에는 role grant/revoke 기능을 넣지 않음

### 7. 공급자 신뢰 파이프라인

문제:

- AI 분석과 QR 인증만으로는 수요자가 실제로 좋은 나눔을 받았는지까지 설명하기 어려움
- 공급자 신뢰가 화면에서 충분히 드러나지 않음

해결:

- 수령 QR 인증으로 `completed`가 된 받은 나눔에만 평가/신고 허용
- 별점 대신 `상태가 좋아요`, `사진과 비슷해요`, `찾기 쉬웠어요` 같은 태그 기반 평가 도입
- 신고는 태그가 아니라 라디오형 단일 사유와 처리 상태를 가진 운영자 검토 대상으로 설계
- 나눔 상세와 프로필에 `QR 보관 인증`, `수령 완료 기록`, `좋은 평가`, `최근 신고 검토 없음` 뱃지 노출

## 12. 발표 구성 제안

1. **문제 제시**
   - 최재원 씨가 유통기한 임박 식재료를 발견한 상황
   - 기존 대안의 번거로움

2. **서비스 소개**
   - FoodLink 한 줄 정의
   - 공급자/수요자 핵심 가치

3. **사용자 흐름**
   - 공급자: 촬영 -> AI 확인 -> 냉장고 선택 -> QR 보관
   - 수요자: 홈/지도 확인 -> 신청 -> 30분 선점 -> QR 수령

4. **핵심 기능 시연**
   - AI 분석
   - 나눔 등록
   - 지도/냉장고 탐색
   - 나눔 신청
   - QR 인증
   - 수령 경험 평가와 공급자 신뢰 뱃지
   - 알림

5. **기술 구현과 이슈 해결**
   - AI 메타데이터
   - FCM
   - QR 시간대
   - Android safe-area
   - 운영자 권한
   - 공급자 신뢰 피드백 계약

6. **마무리**
   - FoodLink는 버리기 전 마지막 선택지를 생활 동선 안에서 만든다.
