# FoodLink 서비스 흐름 UI 점검 설계

> 날짜: 2026-06-04
> 브랜치: `codex/service-flow-ui-polish`
> 목적: 핵심 기능 화면을 빠르게 훑고, 발표/데모에서 크게 보이는 UI/UX 문제를 우선 수정

## 결정 사항

- 백엔드 핸드오프 문서는 최종 계약으로 간주한다.
- "페이지 수정 안 보인다" 피드백은 우리 개발 범위와 무관하므로 제외한다.
- 영상과 기능별 이미지는 빠르게 촬영 가능하므로, 1차 작업은 UI 점검과 상위 이슈 선별에 둔다.
- 점검 방식은 하이브리드로 진행한다. 먼저 코드/문서 기준으로 위험 지점을 좁히고, 가능한 실제 앱 화면으로 확인한다.

## 1차 점검 범위

다음 핵심 화면을 대상으로 한다.

- 로그인, 회원가입, 위치 등록
- 홈
- 지도와 공유 냉장고 탐색
- 촬영 또는 이미지 선택
- AI 분석 결과
- 나눔 식재료 등록
- 공유 냉장고 선택
- QR 보관 인증
- 나눔 상세와 요청
- QR 수령 인증
- 리뷰, 신고, 신뢰도 반영
- 프로필과 내 나눔/받은 나눔 흐름

## 점검 기준

이슈는 다음 기준으로 분류한다.

- 치명적: 발표/데모 흐름을 막거나, CTA가 가려지거나, 사용자가 다음 행동을 이해하기 어려운 문제
- 발표에 거슬림: 텍스트 깨짐, mock/QA 문구 노출, 디자인 시스템과 어긋난 화면, 시각적 완성도가 낮은 문제
- 나중에 정리: 장기적인 디자인 시스템 정리, asset 개선, 큰 구조 변경

## 1차 수정 원칙

- 전체 리디자인은 하지 않는다.
- 발표 영상에 바로 보이는 상위 3-5개 문제만 먼저 수정한다.
- 디자인 시스템 컴포넌트가 이미 있는 경우 새 스타일을 만들기보다 기존 DS 컴포넌트를 우선 사용한다.
- 코드 변경은 화면별로 작게 유지하고, 관련 없는 리팩터링은 제외한다.
- 수정 후 가능한 좁은 테스트와 타입/린트 검증을 수행한다.

## 서브에이전트 점검 분담

서브에이전트는 읽기 전용 점검자로 사용한다.

- Agent A: 온보딩, 홈, 프로필 흐름 점검
- Agent B: 지도, 냉장고 선택, 나눔 상세/요청 흐름 점검
- Agent C: 촬영, AI 분석, 등록, QR 보관/수령 흐름 점검
- Agent D: 리뷰, 신고, 신뢰도 설명 문서와 발표 스토리 점검

각 에이전트는 다음 형식으로 보고한다.

- 확인한 파일과 화면
- 발표/데모에서 위험한 UI 문제
- 디자인 시스템 또는 asset 불일치
- 빠르게 고칠 수 있는 수정안
- 나중에 미룰 항목

## 산출물

- 화면별 UI 점검 요약
- 상위 수정 후보 3-5개
- 필요 시 기능별 이미지/영상 촬영 체크리스트
- 리뷰/신고/신뢰 시스템 설명 문서 보강안
- 실제 수정 코드와 검증 결과

## 2026-06-05 P0/P1 진행 결과

- P0: 프로필 `냉장고 QR 인증` 직접 메뉴를 제거해 `mode/postId` 없는 QR 샘플 화면 노출을 막았다. QR 진입은 냉장고 선택, 홈 진행 중인 나눔, 상세, 내 나눔/받은 나눔처럼 생명주기 context가 있는 경로만 유지한다.
- P0: 나눔 등록 화면의 `백엔드 분리 등록 계약` 문구와 즉시 공개처럼 읽히는 안내를 제거하고, 대표 식재료 선택 및 `QR 보관 인증 대기 상태` 흐름으로 정리했다.
- P1: 로그인 오류의 `SSH 터널`, 신고 화면의 `운영자 처리 분류`, 프로필 이미지 `/static/uploads/...` placeholder 같은 내부/개발 문구를 사용자용 문구로 교체했다.
- P1: 홈/프로필의 visible `준비 중` 지표를 제거했다. 홈은 `진행 중인 나눔`, 프로필은 수령 완료/좋은 평가 신뢰 요약을 표시하며, impact 숫자는 live VM 확인 전까지 연결하지 않는다.
- 검증: P0/P1 화면 테스트, QR lifecycle 회귀 테스트, trust/impact 계약 테스트, `npx tsc --noEmit`, `git diff --check`를 통과했다.
